# A-share 2.0 一主三辅业务合同（Phase 1 / v1）

## 1. 文档目的

这份文档定义 A-share 2.0 在 **Phase 1** 的正式 business contract：

- 谁是主 Agent，谁是三个辅 Agent
- 每个 Agent 的业务职责与非职责
- 早 / 中 / 晚 的交付边界
- 各 Agent 输出如何汇总为主报告
- 哪些属于本阶段必须做到，哪些明确后置

这不是实现细节文档。

它的作用是：在产品、业务、数据、报告实现之间，先建立一个可以稳定执行的统一口径。

---

## 2. Phase 1 的核心定义

### 2.1 产品形态

A-share 2.0 在本阶段只定义 **A 股业务闭环**，采用：

- **一主 Agent**：A 股主 Agent
- **三辅 Agent**：宏观辅 Agent / 商品辅 Agent / AI 科技辅 Agent
- **三时段节奏**：早 / 中 / 晚
- **双层输出**：
  - short briefing（适合即时阅读）
  - structured long report（适合归档、复盘、后续扩展）

### 2.2 一主三辅的本质

不是四份平行日报。

而是：

- **主 Agent 负责“当天 A 股主判断”**
- **辅 Agent 负责“为主判断提供关键支持、不确定性修正、以及跨视角验证”**
- 最终对外口径以 **主 Agent 汇总后的主报告** 为准

### 2.3 本阶段的正式业务问题

主 Agent 每个时段必须回答的不是“市场发生了什么”这么宽泛，而是下面三件事：

1. **今天 A 股市场最重要的主线是什么**
2. **这个主线是否正在强化、分化、转弱或切换**
3. **今天该关注的执行重点、验证点、风险点分别是什么**

三个辅 Agent 必须围绕这个主问题服务，而不是各自输出一套独立宇宙。

---

## 3. Agent 角色定义

## 3.1 主 Agent：A 股主 Agent

### 业务职责

A 股主 Agent 负责：

- 形成当天 **A 股主叙事**
- 组织早 / 中 / 晚三个时段的主报告
- 决定哪些 support evidence 应进入最终对外版本
- 对主判断给出：
  - 当前方向
  - 关键验证信号
  - 主要风险与失效条件
  - 次级备选路径

### 主 Agent 不是做什么

主 Agent 不负责：

- 重复做完整宏观日报
- 重复做完整商品日报
- 重复做完整 AI 科技子行业日报
- 直接替代数据层做原始数据清洗与事实判定

主 Agent 的工作重点是 **综合、定调、优先级排序、形成执行语言**。

## 3.2 三个辅 Agent

### 宏观辅 Agent

负责回答：

- 当前宏观 / 政策 / 利率 / 汇率 / 流动性背景，对 A 股主判断是顺风、逆风还是中性
- 哪些宏观变化值得进入当日 A 股主报告
- 哪些宏观噪音不应放大

### 商品辅 Agent

负责回答：

- 大宗商品与资源链价格/结构变化，对 A 股相关行业与情绪的含义是什么
- 哪些商品信号可以作为 A 股行业强弱的验证项
- 哪些商品波动只是背景，不应被误解为主驱动

### AI 科技辅 Agent

负责回答：

- AI / 科技方向内，哪些主题、龙头、扩散链条在强化或退潮
- 哪些细分科技线索具有主线潜力，哪些只是局部噪音
- AI 科技方向是否应被提升为主 Agent 的重点章节

## 4. 一主三辅的工作原则

## 4.1 主从关系

- 主 Agent 拥有最终报告装配权
- 辅 Agent 拥有各自视角内的专业判断权
- 当辅 Agent 与主 Agent 初始判断冲突时，必须进入“证据升级”而不是互相覆盖

## 4.2 不重复原则

三个辅 Agent 必须尽量避免重复主 Agent 已明确承担的工作。

允许重复的只有：

- 为了支持主判断所必须复述的关键事实
- 明确标注为 support evidence 的核心证据

不允许重复的包括：

- 通篇重复市场涨跌描述
- 使用不同措辞重复同一事实
- 把 support note 写成第二份主报告

## 4.3 汇总原则

最终主报告应遵循：

1. 主 Agent 先给主结论
2. 再引入最有价值的 support evidence
3. 最后给出执行结论、风险条件、待验证事项

而不是把四份内容机械拼接。

## 5. 输出结构总览

## 5.1 早（盘前）

目标：

- 建立今日主线预案
- 明确应看什么、不该看什么
- 给出开盘后的验证条件

输出重点：

- 主线预判
- 重点方向 / 重点标的池
- 支持证据
- 风险点
- 开盘验证条件

## 5.2 中（盘中）

目标：

- 检查早盘预案是否被验证或被推翻
- 判断主线是否强化、扩散、分歧或切换
- 给出盘中修正结论

输出重点：

- 当前主线状态
- 与早盘预案相比的变化
- 新出现的重要信号
- 午后观察重点

## 5.3 晚（收盘后）

目标：

- 给出日终结论
- 做主线归因
- 为次日做准备

输出重点：

- 今日主线成败与原因
- 结构强弱与扩散情况
- 关键证据回顾
- 次日优先关注与风险

## 6. Phase 1 范围

## 6.1 Phase 1 必须做到

Phase 1 必须明确并稳定落地：

- A 股一主三辅角色边界
- 主 Agent 早 / 中 / 晚交付合同
- 三个辅 Agent 早 / 晚交付合同
- FSJ（fact / signal / judgment）v1 对象结构
- 章节级 evidence mapping 原则
- data-layer 到 report-layer 的证据等级边界

## 6.2 Phase 1 明确不做

本阶段明确不承诺：

- US 主辅对称体系落地
- 全自动高质量长报告生产稳定上线
- 跨客户/账户个性化主辅模板
- 高频盘中完全成熟的自动判断引擎
- 统一评分系统、回测闭环、因子化归因体系

## 6.3 后续阶段可扩展方向

后续阶段可扩展但不属于本次合同范围：

- US 一主三辅镜像体系
- 客户级 watchlist / 风格偏好 / 风险偏好
- 更丰富的 intraday slot
- judgment quality review / replay feedback loop
- section-level auto assembly 与质检

---

## 7. 成功标准

如果 Phase 1 合同被正确执行，应该满足以下判断：

- Yunpeng 能清楚看懂：主 Agent 今天到底在判断什么
- 三个辅 Agent 的价值清楚且不重复
- 早 / 中 / 晚报告差异明确，不是简单换时间戳
- 每个关键结论都能追溯到 fact / signal / judgment 和对应证据
- 数据层、业务层、报告层可以按这份合同推进实现而不再反复争论边界
